# Contributing to Sonic

Sonic is maintained by the repository owner. Contributions are welcome through issues and pull requests, but changes are not applied directly to the `main` branch by outside contributors.

## Report a problem or request a feature

- Open a GitHub Issue with a clear title, steps to reproduce, expected behavior, and actual behavior.
- For a feature request, describe the problem it solves and the intended behavior.
- Do not include passwords, signing keys, access tokens, private download URLs, or other secrets in issues or logs.

## Propose a code change

1. Fork the repository.
2. Create a focused branch in your fork.
3. Make the smallest practical change and include or update tests where appropriate.
4. Run the relevant checks described in the README.
5. Open a pull request targeting `S0L0-R00T-DEV/Sonic:main` and explain the change, its rationale, and how it was tested.
6. Wait for review. The repository owner decides whether a change is merged.

## Releases and workflow files

Only the repository owner publishes official releases. Do not publish releases, create official version tags, or change release/CI workflows as part of a contribution unless the owner explicitly requests it. Pull requests and issue discussions do not grant permission to publish a release.

## Important

Repository settings—not this document alone—enforce branch protection and release permissions. The `main` branch should require the owner’s review, and official version tags should be restricted to the owner.
